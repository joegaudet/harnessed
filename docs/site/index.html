Write a test harness once. Run it under every runner.

One page-object API for Testing Library, Playwright, Cypress, WebdriverIO, Vitest browser mode, Puppeteer, TestCafe and Ember, with Gherkin on top. The same harness class drives a fast jsdom unit test and a real-browser end-to-end test. 

npm i -D @harnessed-ts/core @harnessed-ts/dom   # plus the driver for your runner

Read the docs npm

What a harness is

A class that drives a component the way a person would, through methods named for what the component does. Tests state intent; the harness owns the DOM wiring. 

@Harness({ host: testId('login-form') })
class LoginFormHarness extends ComponentHarness {
  @ByLabel('Email') private accessor email!: Query
  @ByLabel('Password') private accessor password!: Query
  @ByRole('button', { name: /sign in/i }) private accessor submit!: Query
  @ByTestId('login-error') private accessor errorLine!: Query

  async signInAs(email: string, password: string): Promise<void> {
    await this.email.fill(email)
    await this.password.fill(password)
    await this.submit.click()
  }

  async error(): Promise<string | null> {
    if (await this.errorLine.isAbsent()) return null
    return this.errorLine.text()
  }
}
jsdom, via Testing Library
render(<LoginForm />)
const form = new LoginFormHarness(dom({ user: userEvent.setup() }))
await form.signInAs('ada@example.com', 'hunter2')
expect(await form.error()).toBeNull()
A real browser, via Playwright
const form = new LoginFormHarness(pw(page))
await form.signInAs('ada@example.com', 'hunter2')
await expect(form).toBeAbsent()

Setup

Every runner needs @harnessed-ts/core and standard decorators; see required setup.

Testing Library (jsdom) 
npm i -D @harnessed-ts/core @harnessed-ts/dom @testing-library/dom @testing-library/user-event
import { dom } from '@harnessed-ts/dom'
import '@harnessed-ts/dom/matchers' // toBeAbsent, toBeSelected, toReadAs
import userEvent from '@testing-library/user-event'

const { baseElement } = render(<LoginForm />)
const form = new LoginFormHarness(dom({ user: userEvent.setup(), container: baseElement }))
await form.signInAs('ada@example.com', 'hunter2')
expect(await form.error()).toBeNull()
Playwright 
npm i -D @harnessed-ts/core @harnessed-ts/playwright
import { pw } from '@harnessed-ts/playwright'
import '@harnessed-ts/playwright/matchers'
import { expect, test } from '@playwright/test'

test('checks out', async ({ page }) => {
  const checkout = new CheckoutPage(pw(page))
  await checkout.goto({ token: 'abc' })
  const confirmation = await checkout.placeOrder()
  await expect(confirmation.heading).toReadAs('Thanks!')
})

Cypress 
npm i -D @harnessed-ts/core @harnessed-ts/cypress @harnessed-ts/chai \
  @testing-library/dom @testing-library/user-event
import '@harnessed-ts/cypress/support'
import { harnessedChai } from '@harnessed-ts/chai'
chai.use(harnessedChai)

it('signs in', () => {
  cy.visitPage(LoginPage)
  cy.harness(LoginFormHarness, async form => {
    await form.fillIn({ email: 'ada@example.com', password: 'hopper' })
    await form.submitIt()
    await expect(form).to.readAs(/Welcome/)
  })
})

Use cases

One harness from unit test to end-to-end

Write selectors once. The harness that drives a component in a jsdom unit test drives the same component in a real browser, so the end-to-end suite never grows a second set of selectors that drifts out of step with the first.

Behaviour is held to the same rules under every driver: absence answers immediately, single-target operations are strict, and scopes don't leak. See the guarantees.

Page objects

@harnessed-ts/page gives one test object per screen: what it's made of, how to know it has arrived, and how to get there by URL. Pages construct under every driver; only goto() needs one with an address bar. 

@Harness({ host: testId('page-checkout') })
class CheckoutPage extends PageHarness<{ token: string }> {
  override get path() {
    return '/checkout?token=$token'
  }

  @ChildHarness(CartHarness) accessor cart!: CartHarness

  protected async waitForReady(): Promise<void> {
    await this.self.waitFor('visible')
  }

  async placeOrder(): Promise<ConfirmationPage> {
    await this.cart.checkout()
    return this.transitionTo(ConfirmationPage)
  }
}

BDD with Gherkin

@harnessed-ts/gherkin adds a page registry, a {page} parameter type and a world for playwright-bdd, cucumber-js, Cypress cucumber and ember-cli-yadda. Steps call harness methods, not selectors. 

Feature: Checkout
  Scenario: Paying for the cart
    When I open the checkout page
    Then the total is "$90.00"
When('I open the {page} page', async ({ page, world }, name) => {
  world.checkout = pages.open(name, pw(page))
  await world.checkout.goto()
})

Then('the total is {string}', async ({ world }, total) => {
  expect(await world.checkout!.total()).toBe(total)
})

Tooling

  • @harnessed-ts/eslint-plugin: keeps selectors out of tests, and keeps harnesses speaking in behaviours rather than runner or DOM vocabulary.
  • @harnessed-ts/chai and @harnessed-ts/qunit: absent, selected and readAs assertions for runners that don't use expect.extend.
  • @harnessed-ts/config: one harnessed.config.ts for shared settings such as the test-id attribute.
  • @harnessed-ts/claude: installs a Claude Code skill that writes harnesses in your project's conventions. 
// eslint.config.js
import harnessed from '@harnessed-ts/eslint-plugin'
export default [harnessed.configs.recommended]
